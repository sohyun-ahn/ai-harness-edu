# interview

목적: 설계에 필요한 사실을 사용자 입에서 받는다. 짐작으로 채우지 않는다.

## 규칙
- 질문은 **한 번에 하나**, 전체 **최대 7개**. 답을 받은 뒤 다음 질문을 한다
- 사용자가 요청문에서 이미 말한 항목은 묻지 않는다. 그 항목은 「요청문에서」로 표시해 기록한다
- 「알아서」「모르겠다」면 가장 단순한 선택을 하고 **가정**으로 적는다
- 답이 모호하면 예시를 하나 달라고 한다 (파일 한 개 · 실제 문장 하나)

## 질문 순서 (이미 답이 있으면 건너뛴다)
1. 업무 — 지금 누가 무엇을 하는가, 하루 · 한 주에 몇 번인가
2. 입력 — 무엇이 들어오는가 (파일 종류 · 위치 · 예시 하나)
3. 결과물 — 무엇이 나와야 하는가 (형식 · 길이 · 받는 사람)
4. 판단 기준 — 어떻게 가르는가 (규정 · 기준표 · 임계값. 근거 문서가 있으면 위치)
5. 하면 안 되는 것 — 절대 하면 안 되는 행동 (발송 · 원본 수정 · 약속 등)
6. 사람 확인 지점 — 어느 지점에서 사람이 보고 결정해야 하는가
7. 잘했다의 기준 — 결과가 맞는지 어떻게 아는가 (예: 정답이 있는 사례 · 흔한 실수)

## 결과: docs/<이름>/interview.md
- 이름: 업무에서 정한 영문 소문자 · 하이픈 이름 (사용자에게 한 번 알린다)
- 항목 1~7마다: 답변 원문 또는 요약 · 출처(`답변` / `요청문` / `가정`)
- 가정 목록과 「확인 필요」 목록
- 시험용 입력 후보 (7번 답에서 나온 사례 · 흔한 실수)
